# 검증 기록

확인일: 2026-09-23. 환경: 폐기 가능한 로컬 UBI 8.10 컨테이너, DNF 4.7.0.
사용자 서버/회사 프록시에는 접속하거나 패키지를 설치하지 않았다.

- Bash 구문 검사 및 ShellCheck 0.10.0 통과.
- UBI 3개 저장소에서 실제 메타데이터를 다운로드하고 `ubi-check` 실행.
  테스트 이미지에서는 coreutils-single/libxml2/tar 3개 업데이트 후보를 표시했다.
- `rpm-check`에 공식 서명이 있는 OpenSSH 3개, libevent, libtiff를 입력.
  DNF가 UBI의 libedit/jbigkit-libs/libjpeg-turbo 3개 의존성을 추가해 해결했다.
- 두 미리보기 전후 RPM DB 목록의 SHA-256이 같음을 확인했다.
  두 명령의 종료 코드는 1이고 출력은 `Operation aborted.`였다. 설치는 없었다.
- 별도 테스트용 저장소 설정에서 libedit만 제외해 미해결 의존성을 재현했다.
  `rpm-apply`가 의존성 오류로 종료하고 RPM DB가 변경되지 않음을 확인했다.
- 정상 설정의 `rpm-apply`를 폐기 가능한 컨테이너에서 실제 실행.
  공식 로컬 RPM 5개 + UBI 의존 RPM 3개를 설치하고, 서명/트랜잭션 검사 및
  `dnf check`가 통과했다. 테스트 컨테이너는 종료 시 제거됐다.

미리보기 검증 중 DNF의 `--setopt=assumeno=False`가 `--assumeno`를 덮어쓰는 동작을
발견해 모드별로 `assumeno=True/False`를 설정하도록 수정했다. 위 결과는 수정 후 결과다.

실제 RHEL 호스트의 전체 설치 패키지/모듈 조합, 회사 프록시, 커널 설치·부팅·외부 드라이버,
다운그레이드/커널 묶음/모듈 스트림 방지 분기의 실제 대상 서버 재현은 검증하지 않았다.
전체 대상 서버 패키지를 설치한 결과도 아니다.

## 공개 묶음 추가 검증

- 포함된 바이너리 RPM 12개 및 별도 제공 소스 RPM 2개의 SHA-256이 공식
  다운로드 페이지의 값과 일치한다. `RPM-SOURCES.json`에 그 값을 기록했다.
- RHEL 공식 키로 바이너리 12개와 소스 2개의 `rpmkeys --checksig`가 모두
  `digests signatures OK`를 반환했다. RPM 헤더의 버전과 x86_64 아키텍처를 확인했다.
- 공개 스크립트 3개의 Bash 구문 검사와 ShellCheck 0.10.0이 통과했다.
- 공개 `ubi-check`를 다시 실행해 3개 업데이트 후보와 설치 미실행을 확인했다.
- `apply-bundle.sh`는 일치하는 설치 패키지가 없는 최소 컨테이너에서는 설치를 생략했다.
- Perl DBI의 `7c5253dc` 변형은 Perl 5.32 ABI를 요구하므로 포함하지 않았다.
  포함된 `bc962974` 변형은 `perl(:MODULE_COMPAT_5.26.3)`를 요구하며,
  같은 RHSA-2026:69112의 보안 수정이다.
- 포함된 DBI와 UBI 필수 의존성을 폐기 가능한 컨테이너에 실제 설치했다.
  트랜잭션은 총 48개 패키지를 설치했고 Perl 5.26.3-423.el8_10.1을 사용했다.
  설치 후 `dnf check`가 통과했다. 이는 최소 컨테이너의 신규 설치 결과이며,
  기존 서버의 업데이트 개수나 용량을 의미하지 않는다.
- 위 컨테이너에서 `apply-bundle.sh check`가 설치된 DBI만 선택했고,
  모듈 스트림 검사 및 서명 검사를 통과했다. 동일 버전이므로 `Nothing to do.`로
  종료했으며 RPM 목록이 바뀌지 않았다.
- 등록 해제 스크립트는 컨테이너 내 모의 subscription-manager로 검사했다.
  원격 unregister 실패 시 clean/config가 호출되지 않고 인증서가 유지됐다.
  성공 시 unregister → clean → 프록시 설정 제거 순서와 백업 디렉터리 700 권한을
  확인했다. 실제 계정이나 대상 서버의 등록을 해제한 검증은 아니다.

실제 서버 커널 업데이트·부팅 및 회사 프록시를 통한 연결은 여전히 미검증이다.
