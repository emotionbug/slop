# 20260925-5: 보안 패치와 Trivy 판정 보완

이번 릴리스는 이전 설치 묶음에서 추가 업그레이드 가능한 EL8 RPM과 새 보안 패치를 제공합니다.
설치된 패키지 이름만 업그레이드하고 필수 의존성을 추가합니다. 실제 적용 목록은 서버의
`transaction.json`에 기록되며, RPM 개수는 해결한 취약점 개수가 아닙니다.

## 명시적인 CVE 수정

| 패키지 | 수정/확인 내용 | 빌드 검증 |
|---|---|---|
| GNU Wget 1.25.0 release 2 | CVE-2026-58469, 58470, 58471, 58472의 upstream 패치와 후속 회귀 수정 | make check: 129 통과, 18 건너뜀, 예상 밖 실패 0 |
| GNU patch 2.8 release 2 | CVE-2026-56288, 56289 upstream 패치 | 46 통과, 1 건너뜀, 예상된 실패 2, 예상 밖 실패 0 |
| GNU tar 1.35 release 4 | CVE-2026-18477, 18508; 기존 CVE-2025-45582, CVE-2026-5704 수정도 포함 | 226 통과, 25 건너뜀, 실패 0 |
| jq 1.8.2 기존 RPM | CVE-2026-44777 수정 여부를 기존 정확한 RPM에서 확인 | 순환 include: 오류 3으로 차단; 정상 include: 출력 1, 종료 0 |
| 공식 UBI libxml2 2.9.7-21.el8_10.9 | 공식 보안 수정 RPM 및 같은 버전의 개발/파이썬 패키지 | 공식 RPM 서명 및 로컬 트랜잭션 검사 |

Wget의 Metalink 기능은 이 빌드에서 비활성화되어 있습니다. 소스 패치는 포함하지만
Metalink 실행 경로를 활성화해 공격 입력을 재현했다는 의미는 아닙니다.
tar는 공식 UBI의 `tar-1.35-13.el10_2.src.rpm`에 포함된 19개 패치를 순서대로,
fuzz 없이 적용한 뒤 **EL8에서 컴파일**했습니다. EL10 바이너리를 설치하지 않습니다.
tar의 ACL/xattr/SELinux 및 대용량 일부 테스트는 환경 조건 때문에 건너뛴 것으로 남깁니다.

수정 근거는 [reviewed-evidence.json](../native-trivy/reviewed-evidence.json)의 정확한
RPM SHA-256에 연결되며, RPM 헤더와 비설정 일반 파일 해시가 일치할 때만 적용됩니다.
새 버전이라는 이유만으로 모든 CVE가 수정되었다고 판정하지 않습니다.

## Trivy 판정 수정

- OpenSSL의 과거 `1.1.1l` 같은 공식 문자 버전 순서를 해석합니다. 다른 제품의 임의 접미사는 추측하지 않습니다.
- 다른 제품의 CVE에서 SQLite/OpenSSL이 `vulnerable:false` 환경 조건으로만 등장하면 해당 구성요소의 취약 코드로 중복 계산하지 않습니다. 원래 취약 제품에 대한 검사는 별도로 필요합니다.
- 정확히 검토한 `libssh-config`는 설정 전용, `vim-filesystem`은 디렉터리 전용으로 표시합니다. 코드 CVE를 복제하지 않으며 설정/권한이 안전하다는 판정도 하지 않습니다.
- RHEL 8.10의 정확한 perl-DBI `1.641-10.module+el8.10.0+24875+bc962974.x86_64`와 CVE-2026-73194 조합만 공식 CSAF의 수정 제품 목록에 따라 판정합니다. 모듈 context 해시를 버전처럼 비교하지 않습니다.
- 원본 `integrated.json`은 그대로 보존합니다. CSV의 vendor 보정에는 원래 상태·제목·참조 URL도 남습니다.
- 부분 실패한 NVD 조회는 이전 advisory를 유지하고 `query-incomplete`로 표시합니다. 조회 실패를 취약점 없음으로 취급하지 않습니다.

| 결과 | 용도 |
|---|---|
| `actionable.csv` | 남은 vendor 취약점 + 자체 RPM 검토 대상 |
| `fix-available.csv` | vendor 피드에 수정 버전이 기재된 남은 항목 |
| `vendor-actionable.csv` | 공식 OS 패키지 결과 |
| `native-review.csv` | 자체 RPM의 적용 여부를 더 검토해야 하는 CVE |
| `reviewed-resolutions.csv` | 정확한 근거로 수정/비해당을 확인한 항목 |
| `scan-gaps.csv` | 등록, 파일 대조, 피드 범위와 관련된 제한 |

`fix-available.csv`의 버전이 공개 UBI에 반드시 존재하는 것은 아닙니다.
DB와 NVD 피드의 수집 시점도 서로 다르며, 전체 CVE 범위는 계속 미완료로 표시합니다.

## 패키지 구성과 호환성

- elfutils는 EL8의 `elfutils-debuginfod-client` 및 개발 패키지를 함께 제공합니다.
- GDB는 `gdb-gdbserver`를 분리해 기존 gdbserver와의 파일 충돌을 해결합니다.
- Nmap은 EL8의 Epoch 2를 유지합니다. 화면상 버전만 높이고 RPM 비교상 구버전이 되는 문제를 수정했습니다.
- Vim 도구의 `/bin/csh` 의존성을 위한 tcsh를 포함합니다. 기본 로그인 셸과 `/etc/shells`는 변경하지 않습니다.
- 공식 BIND와 `kernel-headers`도 포함합니다. **커널 헤더는 부팅 커널이 아닙니다.** 현재 실행 커널의 CVE가 수정된 것으로 계산하지 않습니다.
- 실행 커널, glibc, systemd, SSH/PAM, 스토리지/네트워크 핵심 서비스의 자체 빌드 전환은 이번 적용 묶음에서 제외합니다.
- libbpf/libevent/libidn/libtiff는 기존 SONAME 의존성이 끊기고, 새 libxslt는 다른 libxml2 ABI를 요구해 제외했습니다.
- GDK-Pixbuf 2.44.8은 EL8 기본 GLib에 없는 네 심볼을 요구하므로 제외했습니다. GTK2와 Graphviz도 제거된 export의 소비자 영향이 남아 적용 묶음에서 제외했습니다. 공통 심볼 이름 일치만으로 실제 충돌이라고 단정하지 않습니다.
- MTR과 OpenJPEG 제작본은 이전 테스트 실패의 원인이 해소되지 않아 제외했습니다. 컴파일 완료를 테스트 통과로 바꾸어 기록하지 않습니다.
- binutils의 문서 호환 수정도 시도했지만 EL8 GCC와의 LTO 링크 테스트 12건이 실패해 적용 묶음에서 제외했습니다. 기존 binutils와 GCC를 유지합니다.

삭제/다운그레이드/다른 패키지 이름으로의 대체는 거절합니다. 의존성이 서버와 묶음에
모두 없거나 실제 소비자가 제거되는 심볼을 사용하면 설치 전에 중단합니다.
컨테이너의 설치·링크·명령 검증은 운영 서버의 부팅, JNI, 보안 에이전트와 Java/Tomcat 실행 증명이 아닙니다.
전체 323종 교체 완료나 취약점 0개 달성을 주장하지 않습니다.
